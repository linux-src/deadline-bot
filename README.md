# deadline-bot

Telegram-бот для контроля временных изменений (баннеры, акции, загрузочные
экраны и т.п.), реализованный по ТЗ «Для контроля временных изменений».

Бот отвечает на один вопрос: **что сейчас временно активно и когда это нужно
убрать**. Каждое изменение обязательно содержит описание, боты, где оно
действует, срок удаления или следующей проверки и ответственного сотрудника.
Бот публикует карточку в отдельный чат/тему, сам присылает напоминания,
помечает просрочку и отслеживает её, пока изменение не подтвердят убранным.

## Стек

- Python 3.11+, [aiogram 3](https://docs.aiogram.dev/) — сам бот и FSM-мастер создания
- SQLite (`aiosqlite`) — хранение изменений и списка сотрудников
- APScheduler — ежеминутная проверка сроков, напоминания, эскалация просрочек

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# заполнить BOT_TOKEN, CARD_CHAT_ID и т.д.

python bot.py
```

Чтобы узнать `CARD_CHAT_ID` (и `CARD_THREAD_ID`, если карточки должны идти в
отдельную тему супергруппы) — добавьте бота в нужный чат и отправьте там
`/chatid`, бот пришлёт оба id.

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен из @BotFather |
| `CARD_CHAT_ID` | чат/супергруппа, куда публикуются карточки и уведомления |
| `CARD_THREAD_ID` | (опц.) id темы внутри супергруппы |
| `BOTS` | список ботов через запятую, между которыми распределяются изменения |
| `TIMEZONE` | часовой пояс для расчёта сроков (по умолчанию `Europe/Moscow`) |
| `REMINDER_MINUTES_BEFORE` | за сколько минут до срока слать напоминание (по умолчанию 60) |
| `ESCALATION_MINUTES` | с каким интервалом повторять «ПРОСРОЧЕНО», пока не подтвердят (по умолчанию 45) |
| `DB_PATH` | путь к файлу SQLite |

Если `CARD_CHAT_ID` не задан, бот на первое время публикует карточку прямо в
тот чат, откуда была вызвана `/temp` — но это временное решение только для
обкатки, для продакшена id чата нужно указать.

## Сценарий работы (как в ТЗ)

1. **`/temp`** (или кнопка «➕ Новое временное изменение» после `/start`) —
   запускает пошаговый мастер: тип изменения → где действует (все боты /
   один / несколько с чекбоксами) → описание → срок (точная дата или «нет
   точной даты» → быстрые опции проверки) → ответственный.
2. По завершении бот публикует карточку **ВРЕМЕННОЕ ИЗМЕНЕНИЕ** с кнопками
   `✅ Убрано`, `⏰ Продлить`, `✏ Изменить` в настроенный чат.
3. Планировщик раз в минуту проверяет сроки:
   - за `REMINDER_MINUTES_BEFORE` минут шлёт `⏰ Напоминание`;
   - в момент дедлайна шлёт `🔴 Срок истёк` / `🟠 Наступило время проверки`
     и переводит статус в «Просрочено» / «Требует проверки»;
   - дальше каждые `ESCALATION_MINUTES` минут повторяет `⚠ ПРОСРОЧЕНО`, пока
     изменение не подтвердят убранным.
4. **`✅ Убрано`** — если бот был один, изменение сразу завершается. Если
   ботов несколько, бот спрашивает «Убрано во всех?» → «Да, везде» или
   «Выбрать боты» (чек-лист по каждому боту); пока не отмечены все — задача
   остаётся активной.
5. **`⏰ Продлить`** — быстрые опции (+1/+2/+3 часа, до конца дня, до
   завтра, своя дата) или свободный ввод даты; карточка обновляется, статус
   сбрасывается на «Активно», отправляется уведомление было/стало.
6. **`✏ Изменить`** — точечное редактирование описания, ботов, срока или
   ответственного без пересоздания карточки.
7. **`/active`** — список всех незавершённых изменений со статусом.
8. **`/today`** — то, что нужно убрать/проверить/продлить/подтвердить
   сегодня (плюс всё, что уже просрочено или требует проверки, независимо от
   исходной даты) — для поддержки в начале смены.

Статусы: 🟡 Активно · 🔴 Просрочено · 🟠 Требует проверки · ✅ Завершено.

## Решения, принятые за пределами буквального текста ТЗ

ТЗ описывает поведение примерами, но не фиксирует несколько технических
деталей — вот как они закрыты и почему:

- **Список сотрудников для «Ответственный».** В ТЗ не сказано, откуда он
  берётся. Бот автоматически регистрирует в списке любого, кто хоть раз
  написал ему (даже `/start`) — специальной админки для этого не нужно.
  Если создатель — единственный, кто писал боту, список будет состоять из
  него одного; попросите коллег, которые должны быть ответственными,
  написать боту `/start`.
- **Ввод даты и времени.** Кнопки «Выбрать дату и время» реализованы как
  запрос текста в формате `20:00`, `12.09 20:00` или `12.09.2026 20:00` —
  полноценный календарь Telegram inline-клавиатурами не рисуется, это
  избыточно для сценария «сегодня/завтра/через N часов».
- **Цвета статусов.** В примере `/active` из ТЗ значок первых двух пунктов
  визуально не совпадает с их же разделом «Статусы» (вероятно, артефакт
  PDF/иконок). Реализация следует явному определению из раздела «Статусы»:
  🟡 Активно, 🔴 Просрочено, 🟠 Требует проверки, ✅ Завершено.
- **«Все боты» и контроль по нескольким ботам.** Выбор «Все боты»
  разворачивается в полный список ботов из `BOTS` и дальше отслеживается
  так же, как явный выбор нескольких ботов (чек-лист при завершении) — в
  ТЗ это не оговорено явно, но пример чек-листа по ботам в разделе «Контроль
  нескольких ботов» подразумевает именно это.
- **Требует проверки → эскалация.** ТЗ описывает повтор «ПРОСРОЧЕНО» только
  для изменений с точным сроком удаления. Для изменений «без точной даты»
  реализована аналогичная периодическая эскалация (`⚠ ТРЕБУЕТ ПРОВЕРКИ`) —
  иначе такие задачи тихо повисали бы без напоминаний до следующего
  ручного /active.
- **Бот-админка отдельно от отдельного бота в чат поддержки.** ТЗ упоминает
  обе идеи. Реализован второй вариант (отдельный бот, публикующий карточки
  в конкретный чат) — он гибче: этот же бот и есть «админка» (создание,
  редактирование, списки), просто без отдельного веб-интерфейса.

## Структура проекта

```
bot.py                  # точка входа
config.py               # переменные окружения
app/
  db.py                 # SQLite: employees, changes
  utils.py              # даты, статусы
  cards.py              # текст карточек/уведомлений, refresh_card
  keyboards.py          # инлайн-клавиатуры
  states.py             # FSM-состояния
  middlewares.py        # автоregистрация сотрудников
  scheduler.py          # APScheduler: напоминания, просрочки, эскалация
  handlers/
    registration.py     # /start, /chatid
    wizard.py            # /temp — мастер создания
    card_actions.py      # кнопки карточки: Убрано/Продлить/Изменить
    lists.py             # /active, /today
```
